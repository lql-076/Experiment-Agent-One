## 3. 核心设计

### 3.1 数据模型

`project.json` 只有 `modules`，没有 `graph` / `edges` / `shots`：

```json
{"modules": [{"id": "voice-white", "type": "voice", "x": 850, "y": 40, "w": 400, "h": 500,
  "params": {"role": "白页", "lines": [{"line_index": 1, "text": "第一句"}]},
  "outputs": [{"rel": "tts/shot01.wav", "kind": "audio", "line": "1", "sha256": "..."}],
  "status": "ok"}]}
```

固定 7 个 id：`script`、`image`、`voice-white`、`voice-zisu`、`bgm`、`compose`、`publish`。只能拖动/缩放，不能增删。

### 3.2 模块间协作：Lists

模块 1 导入剧本 / DeepSeek 拆解 → 一次写 5 份 Markdown：

- `Lists/配音清单_白页.md`
- `Lists/配音清单_紫苏.md`
- `Lists/配乐清单.md`
- `Lists/视频渲染清单.md`
- `Lists/生图清单.md`

模块 2/3/4/5/6 内部都能展开清单编辑，保存后解析回参数。清单的 `## NN` 就是全局 `line_index`。

### 3.3 配音全局句序

- 白页、紫苏各自只跑自己的句子。
- 每句按 `line_index` 写 `tts/shotNN.wav`。
- 任一角色跑完都调用 `_rebuild_voice()`：把两个模块所有已有音频按全局句序拼成 `voice.wav`、`subtitles.srt`、`timeline.json`。
- 逐句仍用 SHA-256 缓存。

### 3.4 模块 6 三窗一体

- 读 `视频渲染清单.md`，决定每镜 `web` / `ppt` / `static`。
- A 窗：Claude Code（可用时）写单文件 HTML → Playwright 逐帧录 H.264；不可用退回内置模板。`render_web` 每若干帧写预览 JPEG，任务状态带 `preview_rel`。
- B 窗：`render_ppt.render_all()` 生成卡片 PNG，后台协程轮询渲染目录，状态带 `slides` 列表。
- C 窗：`video_maker.compose_video(project=投影)`，进度回调写 `pct/msg/log`，参数带画幅/字幕/配乐音量/闪避/编码 FPS。
- 渲染出的 `render_clip` / `render_image` 写回模块参数，单独重跑 FFmpeg 时直接复用。
- 没有配音时 `_make_silence()` 生成静音轨，模块 6 独立可测。

### 3.5 调度

- 全流程：`voice-white`、`voice-zisu`、`bgm` 三个 task 并发；全部结束后重建配音，再进模块 6。
- 模块 6：网页和 PPT 顺序/并行执行（网页先、PPT 后，同一次任务），最后 FFmpeg。
- 生图模块不在全流程里。
- 模块缓存键：SHA-256(模块类型 + 参数 + 依赖产出哈希 + 版本)；模块 6 依赖两份配音、配乐和渲染清单内容。

### 3.6 旧工程迁移

- 没有 `modules` 时先备份 `project.json.v3.bak`。
- 旧 graph 的 image/voice/bgm/mux/publish 和旧 shots 合并成 7 模块；台词按全局句序分进白页/紫苏；网页/PPT 规划写进渲染清单。
- 清掉 `graph`、`edges`、`shots`、`node_layout`。
- 失败恢复 `.bak`。
