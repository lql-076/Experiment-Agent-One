## 核心架构决策

1. **不碰旧页面。** 生图、配音、配乐、发布仍是原来的模块和页面；视频工坊调用 `imagegen` 的低层 `card/build_prompt/CALL`、`tts` 的配音服务、`bgm.B.generate`、`publish.check_item/ask`。生图不写 `data/img/board.json`，配音不覆盖「配音」页的试听稿。
2. **工程文件夹就是状态。** `工作区\视频工坊\<项目名_时间戳>\project.json` 记录四步状态、分镜、文件相对路径、成本；后端重启后读它恢复，不依赖内存。`Agent 重启时正在跑` 的步骤会标成「中断」，可以单步重跑。
3. **时间轴以配音为准。** 每镜配音单独存 WAV，拼成 `voice.wav` 时记录真实 `start/end`（含 0.25 秒停顿）；SRT 按台词在逗号处切分、按字数分配时间；合成时每个分镜展示 `end-start` 秒，图片不够就循环，画面比配音短就 `tpad` 补最后一帧。
4. **画面不呆板。** `zoompan` 三种镜头轮换：推近、拉远、横向微移；输入放大到 2 倍目标分辨率再裁切，1080×1920 / 1920×1080、30fps。
5. **声音不吵。** 配乐 `-stream_loop -1` 循环到总长，`volume` 压低后由人声做 `sidechaincompress` 侧链，无人声时自动抬升；结尾 2 秒淡出。
6. **字幕避开抖音底部。** libass 烧录，白字黑边；竖屏 `MarginV=76`、字号 18，横屏 `MarginV=42`、字号 22；`FontName=Microsoft YaHei`。
7. **显存串行。** 本地配音前关配乐服务；配音出完、配乐前关配音服务。16GB 上不同时加载两个模型。云端配音不需要显卡，不参与这个串行。
8. **停下是安全的。** FFmpeg 用 `-progress pipe:1` 回进度；停下时 `terminate`，4 秒不退再 `kill`，删 `.part.mp4`，不留下半截成片。子进程一律 `CREATE_NO_WINDOW`。
9. **发布绝不绕过人工。** `to_publish` 只调用 `publish.ask()` 放进 `pub_pending` 待确认队列；「发布」窗口点两下才发。同一条视频重复点不会重复入队。
10. **界面一屏。** 三栏（参数 / 分镜 / 预览），只有 `.st-shots` 分镜列表内部滚；竖屏改成输入在上、分镜在下、预览在右。操作偏好进 `uiState` 的 `U.studio`。

## 重要注意（本机测试副作用）

这一轮在本机（不是 Linux 沙箱）直接跑了 `dev/serve.sh`，它按沙箱习惯把 `data/secrets.bin` 里的 **DeepSeek / API易 / 百炼三个 Key 写成了假值 `sk-test-0000`**。发现后已经：

- 把 `data/settings.json` 的服务地址恢复成官方地址（`api.deepseek.com`、`dashscope.aliyuncs.com`、`api.apiyi.com`、`bgmUrl 8094`、`imgOut` 空、`ttsEngine cloud`）；
- 把三个假 Key 清空（`qqSecret` / `hfToken` 没动）；
- 删除测试建的 3 个视频工坊项目、丢掉测试的发布待确认条目、清掉对应的配乐历史。

**如果这三个 Key 原来是真 Key，需要作者到 设置 › 云端 重新填一次。** 这是本轮的操作事故，不是代码问题；后续在本机跑 `dev/serve.sh` 前应先备份 `data/`，或者只在 Linux 沙箱里跑。

## 待办 / 限制

- 真实 DeepSeek 拆解的分镜数量、口播字数和目标时长是否合适，要在作者电脑上用真 Key 试。
- 真实 API易 生图的画幅、人物一致性、出图时间；真实 Qwen3-TTS / Breeze / Stable Audio 3 的显存串行释放和音质。
- FFmpeg 在作者显卡上的合成速度 / zoompan 观感；libass 字体和竖屏字幕位置在真机抖音里的实际遮挡情况。
- 目前视频工坊的音色列表是本机预设 + 我的音色 + 百炼音色；没有做「每镜不同音色」的批量分配（一条视频统一一个音色）。
- 配乐闪避参数（threshold 0.03、ratio 8、attack 30、release 550）是保守默认值，真机听感不合适时再调。
- 没有把 BGM / 配音 / 生图的历史记录做成工坊专属视图；工坊只读项目文件夹，旧页面历史不受影响。
