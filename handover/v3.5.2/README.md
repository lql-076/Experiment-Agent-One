## 这一版解决什么

1. **Breeze TTS 2 慢：** 之前 `app/breeze_run.py` 过滤了官方 `--fast-*`，实际跑 eager；Windows 没有 flash-attn。现在默认 **SDPA + backbone/depth CUDA Graph**（不依赖 Triton），RTF **14.9 → 约 1.1**，稳定后 TTFA 约 **0.5~1.9 秒**；9/19 秒中文音频真实浏览器播放稳定后 **0 次断续**。
2. **前端预缓冲修正：** 第一块 PCM 到达后才开始 1 秒预缓冲；不再把 TTFA 时间吃掉。Breeze 每块提前 350ms 排期。
3. **显存 80/50 策略：** Breeze 默认常驻；**扣除 Breeze 自己后**占用 ≥80% 立刻卸载；卸载后 <50% 连续 10 分钟自动加载；关语音/改本地配音/打游戏让路也释放。用“扣除自己”的占用，是因为模型自身约 10GB，按总占用会刚加载就超过 80% 自己卸自己。
4. **预热：** 不在 Agent 启动时占 10GB；按话筒开始说话或确定朗读时 `POST /api/voice/warm` 后台加载。
5. **接口卡顿：** 硬件采样（PDH/WMI 慢时 3~5 秒）移出后端事件循环，`/api/voice` 和 Breeze 首包不再被它拖住。

## 限制

- `graph` 在 5060 Ti 上 RTF 约 1.1，不是 H100 的 0.32；官方 `compile`/`all` 可以再快一点，但冷启动约 70 秒且更挑显存/Windows，默认不用。
- 80/50 阈值按“扣除 Breeze 自己后”的占用算；如果要改成按总显存算，需要重新设计，否则模型会自己卸自己。
- Windows CUDA Graph / SDPA 只在作者机器验证；换显卡/驱动可能需要退回 `eager`。
