# R10 · v3.9.0 视频工坊重构 · 现状摸底与分阶段计划

> 写于 2026-11-18，开工前。版本号 v3.9.0。

## 一、现状摸底（v3.8.1 / R09）

### 1. 节点怎么存

- 工程文件是 `工作区/视频工坊/<项目名_时间戳>/project.json`（`app/video_maker.py` 的 `PROJECT_FILE`）。
- 节点不是真正的图：`shots[]` 是分镜/台词数组，界面把它画成「节点 2 生图子工作流」和「节点 3 配音子工作流」里的两列子节点。
- 8 个固定顶层节点只存在于前端：`ui/js/studio.js` 的 `ST_LAYOUT`（1~8 的 x/y/w/h），保存到 `project.json` 的 `node_layout`（键是 1~8 的数字）。
- 子节点参数混在 `shots[]` 的每一项里：`image_prompt`、`img_model`、`img_ratio`、`img_resolution`、`img_quality`、`img_complexity`、`img_transparent`、`img_output`、`img_format`、`gif_frames`、`gif_delay_ms`、`img_n`、`img_custom_w/h`、`img_refs`、`role`、`speaker`、`tone`、`text`、`render`、`render_clip`、`render_image`、`ppt_points`。
- 产出也混在 `shots[]`：`image`、`img_variants[]`、`img_selected`、`img_fps[]`、`tts`、`start/end/duration`、`render_clip`、`render_image`。
- 项目级参数在 `settings`：`img_*`、`web_*`、`bgm_*`、`ppt_file`、`role_voices`、`subtitle`、`bgm_volume`、`duck_depth`、`fade`；成片在 `files.video/cover`。

### 2. DAG 怎么调度

- 并没有真实拓扑。`Studio._all()` 写死三路：`_gen_images`、`_gen_tts`、`_gen_bgm` 同时 `asyncio.gather`，全部结束后 `_render_tracks`（网页/PPT），最后 `_compose`。
- 并发控制：`_api_gate()` = `asyncio.Semaphore(4)`（生图 + 百炼云端配音）；`_gpu_lock()` = `asyncio.Lock()`（本地配音 + 配乐串行，换模型前停另一个服务）。
- 分支失败策略：生图全失败才阻塞；配音任一句失败阻塞；配乐失败降级无配乐。
- 单步：`_one()` 按 `images/tts/bgm/web/ppt/video` 调对应方法，`ids` 只重跑指定分镜。

### 3. 缓存键怎么算

- `app/studio_cache.py`：`fingerprint(kind, params)` = `json.dumps({"kind": kind, "params": params}, sort_keys=True)` 的 SHA-256。
- 生图：`_image_fps()` 里 `model + prompt + aspect_ratio + resolution + quality + complexity + custom_w/h + transparent + output_type/format + gif_frames/delay + ref_image_sha256 + n + variant`。
- 配音：`_tts_fp()` 里 `engine + speaker + tone + text`。
- 配乐：`_bgm_fp()` 里 `prompt_en + duration + steps + seed`。
- 双轨：`render_web.render_all()` 的 `track_web` 指纹 = 输入图 SHA-256 + 台词/角色/语气/时长 + 起止 + W/H/FPS + 网页配置；`render_ppt.render_all()` 用 `.pptx` 哈希或卡片内容哈希。
- 存哪：全局 `工作区/视频工坊/_cache/cache_index.json` + `image/`、`tts/`、`bgm/`、`tracks/`；每个项目自己的 `cache_index.json` 存「子节点 key → 指纹 / 相对路径 / 是否命中」。命中就把缓存文件复制到项目产出路径，不再调付费 API。
- 现有失效是「手动打 stale」：`_stale_images`、`_mark(..., "stale")`，不是按图传播。

### 4. 子工作流在哪

- 前端：`node2HTML()` / `node3HTML()` 把 `shots[]` 渲染成 `.st-sub` 两列子节点；`stShotImgHTML()` / `stShotTTSHTML()` 是每个子节点的全部表单。
- 后端：子节点就是 `shots[]`；`add_shot` / `del_shot` 增删；`update()` 把逐子节点参数写回 `shots[]`。
- 剧本导入 `import_script()` / DeepSeek 拆解 `plan()` 直接把结果铺成 `shots[]`，所以「子工作流」不是一个独立数据层，删掉它要同时改前端和 `shots` 这一层。

### 6. 一屏尺寸的实际值（以 `dev/ui/fit.py` 为准）

- 主窗口：横屏 **1680×1000**、竖屏 **1080×1860**（竖屏另测字 130%）。
- 工具窗口：**1440×880**、竖屏 **1080×1860**。
- 需求书里的 1440×880 是工具窗口尺寸，不是主窗口；两者都要过。`fit.py` 的 `SCROLL_OK` 只放过设置操作页（prep/remind/models/cloud/agent/voice/bgm/osd），视频工坊不在里面；画布和节点内部滚动由 `LISTS` 里的 `.st-node-body`、`.st-node-list`、`.st-sublist` 放行。
- v3.9.0 仍按这个实测值：画布外框占满主区域，页面级不滚；只有画布内部和节点内部可以滚。

## 二、分阶段计划

### 阶段 A：高清灯箱（Lightbox）

**后端**
- 新增 `app/studio_assets.py`：只读取图 + 信息。
  - 根只认 `工作区/视频工坊`（含各项目目录和 `_cache`）。
  - 拒绝绝对路径、盘符、`..`、解析后越界、非图片扩展名、伪造文件头。
  - `asset_info()`：真实 W/H、文件大小、GIF 帧数/总时长、SVG 尺寸、SHA-256。
  - SVG 当不可信内容：只按 `image/svg+xml` 返回并带 `Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'`，前端只用 `<img>` 内嵌，不执行脚本。
- `app/studio.py` 加 `GET /api/studio/asset`、`GET /api/studio/asset/info`、`POST /api/studio/reveal`（打开所在文件夹，限制在项目根内）。

**前端**
- 新增通用 `ui/js/lightbox.js`：`Lightbox.open(items, index)`。
  - 滚轮缩放、双击复位、拖动平移、Esc / 点遮罩关闭。
  - 棋盘格 / 深色 / 浅色三档底衬。
  - GIF 原速循环；SVG 用 `<img>`；多张左右切换。
  - 信息栏：W×H、文件大小、GIF 帧数/时长、缓存命中、打开所在文件夹。
- `ui/css/v3.css` 加 `.lb-*` 样式；`ui/index.html` 引入 `lightbox.js`。
- 所有节点产出缩略图/封面/PPT 幻灯片点击都走 `Lightbox.open`。

**测试**
- `dev/test_studio.py`：越界（`..`、绝对路径、符号链接、非图片、伪造 PNG）、`asset_info` 的 GIF 帧数/时长、SVG 尺寸。
- 新增 `dev/ui/lightbox.py`：开关、缩放、棋盘格切换、GIF 播放、多张切换、信息栏数字对得上。

### 阶段 B：自由节点画布（地基）

**数据模型（新 `app/studio_graph.py`）**
- `graph = {nodes: [...], edges: [...]}`，写进 `project.json`（`version: 3`）。
- 节点：`id/type/title/x/y/w/h/params/outputs[{key,rel,sha256,kind,...}]/status/error/cache_key/cache_hit`。
- 连线：`{id, from: "节点id.端口名", to: "节点id.端口名"}`。
- 端口类型：`text / image / audio / video / timeline`；`PORT_DEFS` 定义每类节点的输入/输出端口；`connect()` 校验类型兼容 + 环检测。
- 固定节点：`script`、`mux`、`publish` 各 1 个，`delete` 拒绝；其余 `image/voice/bgm/web/ppt` 任意增删。
- 默认画布：script、image#1、voice·白页（Serena）、voice·紫苏（Vivian 男声预设）、bgm#1、web#1、ppt#1、mux、publish；**0 条连线**。
- `order` 参数决定同类型上游在 mux 里的拼接顺序（新建递增；迁移按原分镜顺序；剧本按任务顺序）。

**调度与缓存**
- `topo_order()` + `run_all()`：无依赖并行，有依赖按拓扑；未连线节点各自独立。
- 缓存键 = `fingerprint("node", {type, params, upstream_output_hashes, model_version})`；沿用 `_cache/` 与 `_cache/tracks/`。
- 改参数只让本节点和下游失效（`invalidate_downstream()` 递归清 `cache_key` 并标 stale）；上游/平行分支不动。
- 单节点运行：先查所有入边上游产出的 SHA/文件，缺就报「缺上游产出：节点 X」；绝不自动跑上游。

**节点执行器（尽量复用现有函数，不复制）**
- 生图：复用 `_gen_images/_image_one`，只在 `shots[]` 投影里加节点 id 作为产出文件名。
- 配音：复用 `_gen_tts` 的本地/百炼分支和 `_build_voice`，按节点输出前缀生成 `tts/<node>_voice.wav/.srt/.timeline.json`。
- 配乐：复用 `_gen_bgm`，加产出名参数。
- 网页：复用 `render_web.render_all()`；节点把连进来的图片、台词、时长投影成一条 shot。
- PPT：复用 `render_ppt.render_all()`。
- 混流：把上游节点投影成 `shots/files/settings`，复用 `video_maker.compose_video(..., project=proj)`。
- 发布：复用 `publish.check_item/ask` 和 `to_publish`，但只有点「送去发布」才入队，全流程不自动发。
- 临时投影项目带 `_transient`，`_save()` 不写盘，避免污染原工程。

**旧工程自动迁移**
- `ensure_graph(p)`：没有 `graph` 才迁移；先把 `project.json` 备份成 `project.json.bak`（已存在不覆盖）。
- 每张分镜图 → 独立 image 节点；每句配音 → 独立 voice 节点（保留 role/speaker/tone/text）；有网页/PPT 的分镜 → 独立 web/ppt 节点；配乐、混流、发布各 1 个。
- 产出文件、`img_fps`、`tts_fp` 和 `_cache` 指纹原样保留，重跑应命中缓存。
- 连线：所有图/音/视频/PPT 节点 → mux，mux → publish；script 单独放。
- 迁移后按类型分列整齐排布；失败恢复 `.bak` 并报错；迁移幂等。

**前端**
- 重写 `ui/js/studio.js` 的画布层：真实节点 DOM + 左边输入端口、右边输出端口 + SVG 贝塞尔；拖动节点/缩放节点/拖动端口连线/点线断开；画布平移缩放/适应窗口；「+ 添加节点」菜单；固定节点删除置灰。
- 只重绘变化的节点：每个节点算 HTML 签名，签名没变就不动 DOM；连线在拖动时 rAF 重算。
- 节点编辑器：script 主题/拆解/导入；image 全参数（普通/GIF/SVG、16 参考图、尺寸校验）；voice 多行台词 + 逐句语气 + 试听；bgm；web；ppt；mux；publish。
- 画布外框占满主区域，无页面滚动。

**测试**
- `dev/test_studio.py`：端口类型校验、环检测、拓扑并行顺序、缓存失效范围、单节点缺上游、迁移（假旧工程→节点数/参数/产出/缓存）、默认画布/固定节点。
- `dev/ui/canvas.py`：添加删除节点、拖动缩放、连线断线、适应窗口。
- `dev/ui/fit.py` 继续过。

### 阶段 C：剧本驱动

- 新 `docs/视频工坊剧本格式.md`：JSON / Markdown schema，含 `shots[].id`、`image`、`voice`、`render`、`bgm.segments[]`、`publish`。
- `studio_graph.import_script_graph(p, text)`：
  - 校验：缺字段、类型不对、行号/字段名，一次列清楚。
  - 稳定 key：`shot-<id>`；同 key 更新参数、保留 outputs/cache_key；剧本里没有的节点标 `script_removed`，不删除。
  - 幂等：同一份导入两次节点数不变。
  - 自动建 image/voice/web/ppt/bgm 节点并连到 mux，mux → publish。
  - 不触发生成；返回预估费用（按张数/字数/配乐段数粗算）。
- 前端 script 节点加「按剧本导入（新画布）」和预估费用显示。
- 测试：schema 校验、导入幂等、增量更新、自动连线。

- web 节点输入端口接 image 节点产出；节点内「交给 Claude Code 看图复刻并录制」按钮。
- 后端 `styleframe` 动作：
  - 先弹确认（前端显示「会消耗 Claude Code 额度」）。
  - 用 `ccode.run()`（`claude -p`，工作目录在工作区，事情从 stdin 给，`CREATE_NO_WINDOW`）。
  - 提示词带 60-30-10、画布尺寸、fps、时长、禁止外部资源、无 logo/商标。
  - Claude Code 产出 HTML 后，用新的 `render_web.render_html_file()`（Playwright 逐帧 → ffmpeg）录成视频，存 `_cache/tracks/` 并带内容哈希。
  - 缓存键 = 参考图 SHA-256 + 提示词 + W/H/FPS/时长；命中不调用 ccode。
  - 失败明确报错、不自动重试；停下按进程号结束。
- 测试用 `dev/fake_claude.py` 走完整流程；不跑真的 claude。
