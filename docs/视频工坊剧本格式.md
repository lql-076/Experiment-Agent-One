# 视频工坊剧本格式（v3.9.0）

「剧本与策划」节点导入的剧本有两种写法：**JSON**（推荐，字段最全）和 **Markdown**（手动改方便）。
导入只建节点、改参数、连好线，**不会自动生成任何东西、不会花钱**；预估费用会显示在界面上，等你点运行才执行。

## 一、JSON 格式

```json
{
  "version": 1,
  "title": "标题，30 字以内",
  "desc": "发布简介，80 字以内",
  "tags": ["AI", "效率工具"],
  "publish": {
    "schedule": "2026-11-20 20:00",
    "declaration": "内容由AI生成",
    "collection": "AI 周报",
    "mode": "single"
  },
  "bgm": {
    "segments": [
      { "id": "bgm-1", "prompt": "upbeat electronic, no vocals", "seconds": 75, "steps": 8, "seed": 20261118 }
    ]
  },
  "shots": [
    {
      "id": "s1",
      "seconds": 6,
      "render": "web",
      "image": {
        "prompt": "暖光书桌前的年轻人，竖屏中景，画面里不要文字",
        "model": "gpt-image-2.6-sunburst",
        "ratio": "9:16",
        "resolution": "2k",
        "quality": "high",
        "complexity": "medium",
        "transparent": false,
        "output": "normal",
        "format": "png",
        "n": 1,
        "refs": []
      },
      "voice": {
        "role": "白页",
        "speaker": "local:preset:Serena",
        "engine": "auto",
        "tone": "冷静吐槽",
        "text": "先说一个反常识的结论。"
      }
    }
  ]
}
```

### 必填

| 字段 | 说明 |
| --- | --- |
| `shots[].id` | 稳定的任务 key。同一份剧本重复导入时靠它对应已有节点，**不要随便改** |
| `shots[].image.prompt` | 生图提示词，40~120 字最好 |
| `shots[].voice.text` | 这一句要念的台词（正文里不要写 `[笑]` 这类标签） |
| `shots[].voice.role` | `白页` / `紫苏` / `旁白` |
| `shots[].voice.tone` | 语气指令，传给本地 Qwen3-TTS 或阿里云百炼 |
| `shots[].render` | `web`（网页动效）/ `ppt`（PPT 卡片）/ `static`（静态 Ken Burns） |

### 可选

- `shots[].seconds`：这一镜大概几秒，默认按台词字数估。
- `shots[].image` 里的模型、比例、分辨率、画质、复杂度、透明、出图类型（普通/GIF/SVG）、格式、张数、参考图。
- `bgm.segments[]`：几段配乐就写几段，每段 `prompt` 必填；`seconds`、`steps`、`seed` 可空。
- `publish`：定时、自主声明、合集、单条/批量；默认单条送审，仍然要「发布」窗口人工点两下才发。
- 发布标题、简介、话题也可以从剧本开头取。

## 二、Markdown 格式

```markdown
# 标题，30 字以内
简介：发布简介
话题：AI 效率工具
定时：2026-11-20 20:00
声明：内容由AI生成

## 配乐 bgm-1
描述：upbeat electronic, no vocals
时长：75
步数：8
种子：20261118

## 分镜 s1
画面轨道：网页
时长：6
画面：暖光书桌前的年轻人，竖屏中景
角色：白页
音色：local:preset:Serena
语气：冷静吐槽
台词：先说一个反常识的结论。

## 分镜 s2
画面轨道：PPT
时长：6
画面：屏幕上的对比图表，冷色调
角色：紫苏
语气：夸张惊呼
台词：等等，这也太离谱了吧？
```

`## 分镜` 和 `## 配乐` 后面跟的是稳定 key（`s1` / `bgm-1`）；不写就按顺序自动编号。
分镜里可以写：`画面轨道 / 时长 / 画面 / 角色 / 音色 / 语气 / 台词 / 生图模型 / 比例 / 分辨率 / 画质 / 复杂度 / 透明 / 出图类型 / 格式 / 张数 / 参考图`。

## 三、导入后怎么落到画布

- 每个 `shots[].id` 生成/更新一个**生图节点**和一个**配音节点**；`render=web` 再加一个网页动效节点，`render=ppt` 再加一个 PPT 卡片节点。
- 图和音都会接到 `FFmpeg 混流压制`，混流接到 `发布与排期`。
- `bgm.segments[]` 每段一个背景配乐节点，音频接到混流。
- 同一份剧本再导入一次：按 key 更新参数，节点数不变；已有产出和缓存留着，参数没变的话运行时直接命中。
- 剧本里没有的旧节点**不删除**，只标成「剧本里已移除」并断开它到混流的线，由你自己决定删不删。

## 四、校验

导入前会逐行检查，出错会指出**第几行 / 哪个字段 / 为什么**，比如：

- JSON 第 3 行第 12 列：Expecting ',' delimiter
- 分镜「s2」缺台词（voice.text）
- 分镜「s3」的角色只能是白页 / 紫苏 / 旁白，写的是「张三」
- 分镜「s4」的画面轨道只能是 web / ppt / static，写的是「网页动画」

缺字段、类型不对不会静默跳过。

## 五、v4.0.0 的用途

这份剧本只给 `[模块 1] 剧本与策划` 导入/DeepSeek 拆解用。导入后会立刻生成项目 `Lists/` 下的 5 份 Markdown 清单：

- `配音清单_白页.md`、`配音清单_紫苏.md`
- `配乐清单.md`
- `视频渲染清单.md`（每一镜用网页动效还是 PPT 卡片）
- `生图清单.md`（可选，只给生图测试台手动测图）

之后各模块直接读清单工作，不再需要端口和连线。
