## 做什么

侧栏「后台」：一眼看到它现在在干什么、各个部分好不好、每一步的进展和原始日志。

## 页面上有什么

| 一块 | 内容 | 数据从哪来 |
| --- | --- | --- |
| 正在做 | 一键补齐跑到第几步、进度条、最新一句进展、已经跑了多久 | `/api/monitor` → `setup.status()` |
| 各个部分 | 9 项，每项带 PID、内存、运行时长：后端、本地模型服务、Kev、配音服务（在线时写装着哪个模型、用的什么注意力）、QQ、硬件监控助手、DeepSeek（余额、24 小时调用次数）、每日差事（上次什么时候）、排队的事 | `app/monitor.py` `services()` |
| 进展报告（默认标签） | 一条一条写成人话：第几步开始、测了哪些源各多快、下载进度（原地更新，结束后变成"完成 · 大小 · 用时 · 平均速度"）、装了哪些包、DeepSeek 的判断、要你做什么、汇总；每日差事、训练询问、各部分上下线 | `app/feed.py`，`/api/feed` |
| 原始日志（后面的标签） | 补齐 1~6、后端输出、桌面窗口、模型服务、Kev、配音服务 | `data\logs\*.log`，`/api/logs/<名字>` |

- **刷新：** 打开这一页时，任务和服务每 2 秒刷新，进展报告和日志每 1.5 秒；切走就停。
- **秒开：** 上次拿到的数据一直留着；程序启动后先预取一次，鼠标移到「后台」按钮上也预取，所以点开不会先空一下。
- **竖屏：** 三块一屏放下，进展报告占剩下的高度，自己在里面滚。

## 进展报告怎么来的

`app/feed.py`：

- **条目种类：** 每条有时间、哪件事、哪一步、种类。种类有：
  - 开始 / 结束
  - 一步开始
  - 普通
  - 好了
  - 要注意
  - 出错
  - DeepSeek 的判断
  - 进度
- **进度行：** 同一件事的进度原地更新，不刷屏；20MB 以下的小文件合成一行；只是转圈的阶段（测速、检查文件）结束后删掉，结论另有一句话。
- **谁来写：**
  - 一键补齐的每一步（`setup.py`）；
  - 脚本的 `@@SAY` 讲解；
  - pip 的"装好了哪些包""报错"；
  - 每日差事（`nightly.py`）；
  - 训练询问（`growth.py`）；
  - 后台照看看到模型服务、Kev、QQ 上线或停了（`main.py` `_watch`）。
- **保存：** 内存里留最近 600 条；进度行以外的每条都写进 `data\logs\report.jsonl`。后端重启后读回最近 200 条，变暗显示，中间隔一行「以上是之前的记录」。

## 日志

- `backend.log`：后端打印的东西都写进来（带时间）。v1.8 起平时没有黑窗口，出了问题先看这里，超过 5MB 就从头写。
- Windows 的行尾是 `\r\n`，读日志时先去掉行尾的 `\r`，再取进度条原地刷新的最后一段。
- 日志名只允许字母、数字、点、横线，防止读到别的文件。
- **无害噪音不打印（v1.8.5）：** Windows 上对方先断开连接时，asyncio 会打一大段「远程主机强迫关闭了一个现有的连接」（`ConnectionResetError` 10054），以前 backend.log 里几百条，把真正的报错淹掉了。后端给事件循环装了 `monitor.quiet_handler`，只吞这一种；硬件监控助手的 HTTP 服务（`hw_helper.Srv`）也不再为对方断开打堆栈。
- **桌面窗口 `window.log`（v3.3.2）：** pythonw 没有黑窗口，窗口自己的 stdout/stderr、`faulthandler`、未捕获异常、线程异常、pywebview 的 logger 都写进这里；启动时超过 5MB 先轮转成 `window.old.log`。后台页的日志标签里叫「桌面窗口」。
- **崩溃记录 `crash.log`（v1.8.5，v3.3.2 加轮转）：** 后端一起来就用 `faulthandler` 把底层崩溃（Python 自己来不及打印报错的那种）写进这里，每次启动先写一行「===== 时间 后端启动 · 进程 N」。超过 5MB 启动时轮转成 `crash.old.log`，不再让一次访问违例写成几十 MB。
- **上次是不是正常退出的（v1.8.5，`monitor.start_guard`）：** 后端运行时 `data\logs\running.json` 记着进程号、起来的时间、最近一次"还活着"的时间（后台照看每半分钟写一次）。点「退出 Agent」（或者命令行里正常停）会删掉它。下次启动时它还在，就按 `monitor.exit_reason` 判断：最近一次"还活着"比这次开机还早 → 随电脑关机或重启停的（只写 backend.log）；crash.log 里上次那一段有 `Fatal Python error` 或 `Windows fatal exception` → 崩溃了；都不是 → 被结束了（比如在任务管理器里结束了 Python 进程），或者崩溃了没留下记录。后两种写进进展报告。

- `app/monitor.py`、`app/feed.py`。
- `ui/js/monitor.js`：页面、标签页、进度条。进度条和整备卡片共用。

## v2.0：后台在跑什么、刚做完什么、哪项卡住了

作者 11-05：生图和配音同时在跑，界面进了常驻屏什么都看不到；10-29：开机自启后有几项红了黄了，几分钟后自己好了，界面没说在启动，「硌得慌」。

- **后台任务（`reports.tasks()`，`/api/tasks`，也跟着 `/api/state` 每 5 秒给一次）：** 安装配音、一键补齐、生成配音（v1.8.8）、生图（v2.0，`reports.imagegen_job`：批量 / 单张，第几张、这张画了多久、还要多久）。每项：`k`、名字、正在做什么、百分比、速度、还要多久。主页「后台在跑」、常驻屏的进度条、侧栏工具按钮上的小点都用这一份。
- **刚做完（`feed.done()` / `done_list()`，`/api/state` 的 `done_jobs`）：** 生图一批出完、配音生成好了，记一笔：名字、谁做的（API易 / 百炼云端 / 本地）、用了几秒、花了多少。只在内存里，最多 20 条，后端重启就清空；主页「刚做完」把它和对话的事件按时间合在一起。
- **Agent 状态多了两种（`app/agentstate.py` 的 `starting`、`_live`）：**
  - **启动中 · 第 N 秒：** 还在起来的路上（开机后 90 秒内，或者进程起了还没在规定时间里准备好）。每项自己的时间（`GRACE`）：模型服务 180 秒、嵌入模型 240 秒、Kev 300 秒（第一次要下 2GB 权重时 1800 秒）、QQ 60 秒、游戏内显示 45 秒、硬件监控助手 120 秒。
  - **卡住了：起了 X 还没好：** 超过这个时间还没好，或者进程在但不响应。旁边一个「重启」按钮：`POST /api/agent/restart/{k}`（模型服务、Kev、QQ、游戏内显示；只重启我们自己开的进程，按 PID 停），进展报告里写一句「你在 Agent 状态里点了重启：……」。
  - 头部那句写「N 项卡住了」「N 项启动中」。
- **安装配音看得清（`tts_install.ST["steps"]`）：** 每一步一行：跳过（已经装好 / 已经下好）、新装（这次装的、下好的）、进行中、失败（带原因）。来自安装脚本的 `say(…, "✓")` 这些进展报告（`step_say`）。设置 › 本地模型 的「安装配音」那块列出来。


## 全链路行为遥测（v3.5）

- **存哪：** `data\logs	elemetry	race_YYYY-MM.jsonl`（结构化）+ `behavior_YYYY-MM.log`（人看）。按月追加，不覆盖；不是 5MB 轮转。
- **Schema：** `ts/time/trace_id/cat/action/target/status/dur_ms/metrics/msg`。
- **前端：** `ui/js/telemetry.js` 在主窗口和所有工具窗口加载；事件委托记录点击、开关、快捷键、窗口打开/关闭/缩放；`window.onerror`、`unhandledrejection`、`longtask > 200ms`；所有 `<audio>` 的 play/waiting/stalled/error/ended；每 500ms 或 15 条批量上报，页面隐藏/离开用 `sendBeacon`。
- **Trace ID：** 每次交互生成 `tr_...`，随后 `fetch` 自动带 `X-Trace-Id`；后端中间件用同一个 id 记录接口耗时/状态码。
- **语音诊断：** `voice.stream_start`、`voice.first_chunk`（TTFA）、`voice.underrun`（断流次数、停顿毫秒、RTF、最大分块间隔）；warn/err 自动附 GPU 占用、显存、活动子进程快照。
- **后端：** 所有业务接口记 `trace_id`、路径、耗时、状态码；高频轮询采样 3%，慢和错全记。`Proc` 记录启动原因、PID、就绪耗时、显存前后、退出码；Claude Code 记开始/完成/停下。
- **窗口生命周期（v3.5.1）：** `cat=proc` 的 `action=launch_ok / launch_hung / launch_fail / close_cascade / window_force_exit / window_closed`；带目标进程 PID、HWND、工具窗口数、耗时和原因，启动.bat 拉窗口、卡死重启、主窗口级联关闭都能在后台 › 行为监控 › 接口与子进程里查。
- **界面状态（v3.5.1）：** `cat=ui` 的 `theme_change / state_save`；只记主题、改了哪些键，不记具体文案。
- **后台页：** 「行为监控」标签：全部行为 / 按键与界面 / 语音与配乐诊断 / 接口与子进程 / 仅看异常与慢响应；支持关键词/trace_id 搜索。列表自己滚，页面一屏放下。上次停在行为监控时重新打开也会先画筛选条和空状态，不再是空白块。

## 日志定期归档（v3.5）

- **周期：** `logRetainDays` 默认 180 天，可切 365 天；设置 › 数据 有「立即执行一次归档整理」。
- **触发：** 每日差事和启动自检调用 `log_archive.maybe_run()`。
- **先备份：** 扫描遥测、crash/window/backend/setup/report/actions 日志，生成《重要事项永久备份》（Markdown + JSON）到 `data\logs\important_backups\` 和 `工作区\备份\日志重要事项\`：崩溃/子进程异常、语音断续与慢接口 Top 10、配乐/配音/Claude Code/整备统计、显存让路与峰值。
- **后清理：** 过期原始分片/旧日志压缩成 `data\logsrchive\logs_before_YYYY-MM-DD.zip`，成功后删除过期分片；最近 30 天热日志和永久备份永远保留。
- **隐私：** 报告只放聚合统计、错误类别、接口路径、子进程名；不写聊天/提醒原文、密钥、账号。
