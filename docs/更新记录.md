每一版改了什么。更新方法：新压缩包解压到原来的 Agent 文件夹，选「替换」，再双击 `启动.bat`。

## v1.8.16（2026-10-30）

- **默认模型换成 GPT Image 2.5 Sunburst VIP（按次 $0.03/张，画质够）。** v1.8.15 默认的是按 token 计费的官转模型，画质开高一张能到 $0.17。升级后旧设置自动换成 Sunburst VIP、画质「高」、2K、一张一张出（只换一次）。
- **模型在页面右上角换，不用去设置：** 点一下弹出按厂商分好的列表（Google、OpenAI、Seedream、Flux、xAI），每个模型标着推荐、官转 / 逆向、按次多少钱 / 按量、大概多少秒、当前不稳定，带一句说明。「刷新模型列表」用你的 API易 Key 问一遍现在有哪些（新出的模型也会出现，你的 Key 用不了的标出来）；没列出来的能手动填 ID 试。Nano Banana、Seedream、Flux 各按各家的方式调。
- **四个标签：**
  - **单张：** 写一句提示词出图（文生图），也能放参考图（拖进来、点、Ctrl+V 粘贴）照着出；选比例（10 种，写着像素）、一次 1~4 张、透明背景。

  - **模板：** 单张里点「存为模板」把提示词、参考图、比例、张数、模型存起来，下次一点「套用」就填好。
- 档位 1K / 2K / 4K（VIP 那 30 档尺寸）、画质在页面上面一排换。设置 › 云端 只剩 API易 Key 和接口地址。

## v1.8.14（2026-10-30）

- **修：配音时间轴还是对不上（用自己设计的音色时更差）。** 查出来是**百炼对自己设计、复刻的音色不返回每个字的时间**，只能按停顿猜；猜的时候英文、数字按字母数算长短（VoiceStudio 算成 11 个字），句子配到错的停顿上，后面整串错开；而且还在猜错的地方补了静音，把声音的节奏也弄乱了。
- **加了本地时间轴对齐：** 用阿里开源的 Qwen3-ForcedAligner-0.6B（Apache 2.0，可以商用，约 1.8 GB），拿音频和原文对出每个字的开始、结束，误差几十毫秒。不听写、不联网，跑在配音服务里（用显卡，几秒）。云端、本地生成都用；百炼给了时间戳（系统音色）就直接用百炼的。
  - **要装一下：** 设置 › 本地模型 的「配音」那块多了一行「时间轴对齐模型」，点「接着装」（装过配音的只补这一个，约 1.8 GB，从魔搭下）。
- **猜的不补静音了：** 没装对齐模型、或者在玩游戏让路时，才退回按停顿猜；猜的改成按音节算（英文按音节、数字按中文读法），去掉停顿再比，准多了。但猜的地方不再补静音，声音保持原样。
- **配音页波形下面那行改了：** 对上了是绿的「时间轴：本地对齐，35 句都对上了」；按停顿猜的标红「没对齐，是按停顿猜的，可能对不上」，后面有**「重新对齐」**：试听的那段重新对一遍时间轴，声音不动、不用重新生成、不花钱。时间轴 JSON 的 `check` 里多了 `sure`（是不是有猜的）、`why_not_aligned`（为什么没对齐）。

## v1.8.13（2026-10-30）

- **修：云端配音的时间轴、字幕经常和声音对不上。** 百炼本来就会把每个字的时间和声音一起传回来，问题出在我们换算的时候：百炼文档没写清楚字是一次给全还是一段一段给、时间从整段开头算还是从这一句开头算、会不会先发下一句的开头，以前是猜的。现在三种情况都认：字按位置合起来、每句的起点按这一句自己的声音长度算、两种时间算法都试一遍挑和声音对得上的；百炼返回的原文和发的不一样（读音词典换了字、标点不同）也对得上。
- **时间轴准不准写出来了：** 波形下面一行「时间轴：百炼逐字时间戳，12 句都是准的」；有估的句子、句子边界没落在停顿上的标黄。时间轴 JSON 里也多了 `check`，做视频那边一看就知道能不能直接用。
- 百炼最近一次返回的时间戳原样记一份（`data\tts\last_bailian.json`，不含 Key），再对不上时拿它查。

## v1.8.5（2026-10-28）

- **修：开机自动起来后，整备里总有一两项「缺失」，要手动点重新自检。** 原因是开机时检查得太早：硬件监控助手要 17～34 秒才起来、本地模型服务要 5～30 秒，刚开机网络也可能还没连上，DeepSeek 查不到余额判了缺失还不会自己重查。现在：
  - 开机头 2 分钟里，会自己好的项没准备好时显示「启动中」，不显示「缺失」；后台每 10 秒重查，好了自己变绿。过了 2 分钟还不行才算缺失。没填 Key、Key 不对这种真缺的，照样马上显示缺失。
  - DeepSeek 也加进后台重查（没好的时候才查，好了就不再每半分钟问一次）。
  - 自检窗口里「启动中」的不算「要处理」，单独写「N 项还在启动」。
- **每一项什么时候缺了、为什么，都记下来了：** `data\logs\backend.log` 里搜「自检：」；开机 2 分钟时写一句整备情况；开机之后才变成缺失的，进展报告里也有。
- **Agent 意外停了会留下记录：** 下次启动时，进展报告里写一句上次是怎么停的（崩溃了 / 被结束了；随电脑关机重启停的只记在日志里）。底层崩溃的记录在 `data\logs\crash.log`。
- **修：Agent 被直接结束后，再启动时本地模型服务起不来（端口被占）。** 被结束时它开的模型服务、Kev、游戏内小框还活着，占着端口。现在启动时先把上次留下的这几个停掉再起。只认本项目文件夹里的，别的程序不碰。
- **修：本地模型服务刚起来时偶尔报一次加载错误**（两个请求同时第一次加载）。
- 日志里那几百条「远程主机强迫关闭了一个现有的连接」不再打印（没有坏处，但会把真正的报错淹掉）。

## v1.8.4（2026-10-26）

- **修：每次开机，整备里「本地模型环境（显卡版 PyTorch）」都是缺失，点重新自检也是「检测超时」。** 原因：这项检查每次都另开一个 Python 去加载 PyTorch，刚开机要 20 秒以上，被自检的时限掐断了，结果也没记下来。其实模型服务早就在用这个环境跑着。现在模型服务在线就直接算就绪；它正在启动时显示「检测中」，起来了自己变。
- **修：显卡占用对不上任务管理器（录屏时任务管理器 99%，这边 2%）。** 以前只读了图形 / 计算那部分，漏了视频编码、解码。现在和任务管理器同一套算法：每个引擎算一遍，取最忙的那个；最忙的不是 3D 时，常驻屏和总览写「GPU · 视频编码」。
- **修：CPU 占用、频率不准。** 频率：装了 PawnIO 后，传感器的"各核平均频率"把睡着的核也算进去，偏低，还盖掉了正确的读数；占用：以前的算法不算睿频，比任务管理器低。现在两个都用任务管理器那套 Windows 计数器，传感器只在读不到时兜底。PawnIO 只管 CPU 温度和功耗。
- **显存让路改成按显存算（设置 › 本地模型）：**
  - 别的程序（游戏、画图）占的显存多了，先卸底座和 Kev；还不够，嵌入模型也卸掉，显存全让出来。认出在玩游戏也先让。
  - 显存空出来 3 分钟后自动把嵌入模型装回去；底座还是用到才装。
  - 能调：给别的程序留多少显存（默认 2 GB）、空出来多久再装回去（默认 3 分钟）。原来的「让路的显卡占用线」去掉了。
  - 正在用本地模型回答你时不让，答完再让。每次进出让路都写进进展报告。
- **修：常驻屏硬盘只显示 3 块。** 代码里写死了只取前 3 块。现在有几块显示几块，按任务管理器的顺序，名字前面带盘符（比如「F: Lexar SSD NM710 500GB」）。
