## 1. 概述与核心目标

- **解决什么问题**：把原本各自独立运行的生图、配音、配乐与视频总成，真正无缝打通到同一套七模块零连线画布中，消除前端参数收集错误、任务状态断层、媒体路径缓存失效、以及 Windows 本地子进程（Claude Code / FFmpeg / Playwright）调用阻塞导致的「死活跑不出来」。
- **适用场景**：你在本地 Windows 真机上运行视频工坊进行剧本拆解、双角色配音、背景配乐、独立生图测试与 Claude Code 驱动的视频总成压制；以及在当前在线控制台验证全流程画布、清单联动、实时进度与媒体预览。
- **核心价值**：
  - 消除隐蔽的静默失败（例如音量百分比未换算导致 FFmpeg 爆音、局部重跑误触发全局停止、试听按数组下标错位播放）。
  - 实现真正互不阻塞的多模块并发、精准的实时进度百分比与阶段反馈、以及可诊断的媒体播放体验。
  - 提供清晰可执行的本地 Python 端防卡死与路径转义修复，让 Claude Code 视频合成在 Windows 上稳定跑通。

## 2. 用户体验与交互修复设计

### 关键用户流程（从剧本到成片）

1. **剧本导入与双向清单联动**：
   - 在模块 1 贴入剧本、导入文本或点击 DeepSeek 拆解后，自动生成 5 份 Markdown 清单并立即刷新所有模块参数；
   - 在任意模块展开清单编辑并点击「保存清单并重新载入」，后端即时双向解析回对应模块参数（台词、全局句序、配乐参数、分镜镜头），画布数据实时保持一致。
2. **生图测试台独立调参出图**：
   - 切换清单条目下拉框时，自动把对应条目的提示词、比例与透明背景选项回填到编辑框；
   - 支持本地上传参考图并即时缩略图预览，点击「立即生成测试」绕过旧缓存强制出图，大图直接在顶部预览并支持灯箱查看真实分辨率与哈希。
3. **双角色配音与配乐多模块真并发**：
   - 同时点击白页配音、紫苏配音与背景配乐时，三者各自拥有独立进度条、流光边框、实时阶段文案与秒表计时；
   - 需要使用本地显卡的模型自动进入有序排队状态（「排队中 · 等待上一本地模型释放」），云端与 API 任务直接并发；
   - 顶部「停下」按钮在任意单模块或全流程运行时均可用，点击单模块运行按钮可精准停止该模块而不误伤其他正在运行的模块。
   - 配音模块内点击某一句的「试听/重配」，精确按全局句序（`line_index`）定位对应音频，不再因未配音的空档造成错位播放。
4. **视频制作总成（三窗一体 + Claude Code 驱动）**：
   - 修改配乐音量（0~60%）、闪避深度、淡出秒数、FPS 或画幅后，防抖保存与即时保存统一使用标准浮点比例（`0.00 ~ 0.60`），彻底杜绝 100 倍爆音；
   - 监控 A（网页动效 + Claude Code）、监控 B（PPT 卡片）、监控 C（FFmpeg 压制）实时同步后端进度、预览帧、幻灯片列表、编码帧率与日志摘要；
   - 局部重跑按钮（「仅重跑网页动效 / PPT / FFmpeg」）在合成进行中会自动禁用并提示状态，防止用户误触变成「停下任务」。
5. **媒体播放与错误自检**：
   - 所有音频、视频、图片资源支持字节范围请求（Range 206）与内容哈希防缓存参数，重配或重压后浏览器立即加载最新版本；若加载失败，直接在播放器下方给出可读的后端诊断信息。

### 视觉与交互一致性

- **保留既有指挥舱视觉体系**：严格延续原有的深色夜航 / 浅色日间主题变量、切角 HUD 面板、状态指示灯（待命/排队/运行/完成/出错）及流光呼吸动效，不做破坏性的样式重构，确保你同步到本地后与桌面窗口（PyWebView）风格完全一致。
- **实时反馈强化**：运行中的模块边框保持流光呼吸，进度条平滑推进并显示真实耗时；错误态直接在模块底部及监控窗内给出明确原因（如未填 Key、命令行未找到、转义异常等）与一步恢复建议。

## 3. 关键产品与架构决策

- **决策 1：修复双向契约而非仅改单侧**
  - *选择方案*：同时修正前端画布收集/轮询/播放 Bug 与服务端并发执行/清单双向解析/Range 媒体流接口。
  - *原因*：经排查，卡死与报错并非单点问题，而是前端参数格式（如 `bgm_volume` 百分比、局部重跑事件冲突、`line_index` 错位）与后端并发锁/进程管理/Windows 路径转义叠加造成的。
  - *替代方案对比*：仅修后端会导致音量爆音、停止按钮灰掉、试听错位等前端 Bug 依然存在。

- **决策 2：在线运行时可验证闭环 + 本地 Python 同步补丁文档**
  - *选择方案*：在当前在线 Node.js 服务端完整补齐多模块并发任务池、双向 Markdown 清单解析、DeepSeek 剧本拆解、API易真实生图测试调用（有 Key 时直连）及符合协议的音频/视觉合成产物与 Range 206 媒体接口；同时在内置「说明」模块输出一套专门针对你本地 Windows Python 仓库（`app/studio.py`、`app/ccode.py`、`app/render_web.py`、`app/video_maker.py`、`app/studio_graph.py`、`app/studio_assets.py`）的完整修复清单与可直接替换的代码块。
  - *原因*：容器环境没有你的本地显卡、Windows `claude.cmd` 和 FFmpeg，同时你也不方便上传隐私 Key；这种双轨方案既能让你现在就在在线环境验证全套前端与调度逻辑，又能直接把精准代码覆盖到本地仓库推送 GitHub 测试。

- **决策 3：Claude Code 视频总成的超时守护与平滑降级**
  - *选择方案*：为本地 Windows Python 端的 Claude Code 调用明确指定环境变量清理、`.cmd` 无黑窗执行方式、逐行流式进度读取、单镜产出文件校验，以及失败时的清晰错误展示与可选内置模板兜底机制。
  - *原因*：Windows 上 `claude.cmd` 若直接以普通子进程启动极易因环境变量继承（嵌套会话检查）或编码缓冲区阻塞而无任何响应，必须从进程启动、标准输出异步读取与产物契约三层同时加固。

### 核心数据模型与状态映射

- **模块运行态 (`runtime`)**：每个模块统一维护 `status`（`idle | queued | running | ok | error`）、`pct`（0–100）、`phase`（当前人类可读步骤）、`started_at` 与 `last_took_s`，保证任意多模块同时运行时各自进度条与耗时独立更新，且表单输入期间不破坏焦点。
- **三窗总成态 (`job.web` / `job.ppt` / `job.ffmpeg`)**：后端运行模块 6 时同步更新三窗独立子状态（当前镜头/总镜头、帧号/总帧数、FPS、Claude Code 连接与步骤摘要、幻灯片缩略图列表、FFmpeg 百分比与日志末尾摘要），并在单独重跑某一窗时准确复用另外两窗已缓存的产物路径。
- **双向清单模型 (`Lists/*.md`)**：任何一份清单保存后即刻触发结构化解析器，更新对应模块参数、总时长预估及需要重做的状态标记；解析出错时返回具体行号和字段提示，不静默吞错。

### 关键交互与状态变更映射

- **输入防抖与实时提交**：画布内所有数值型参数（包括 `compose.bgm_volume`、比例、尺寸、时长、步数、种子）在 `input` 防抖阶段与 `change` 阶段保持一致的数值归一化规则，消除两次保存值不一致的竞态问题。
- **模块并发控制与安全停止**：
  - 点击单个模块运行按钮：仅锁定当前模块防重复提交，不影响其余 6 个模块；
  - 点击「从头跑通全流程」：并发启动白页配音、紫苏配音、背景配乐三路任务（自动跳过生图测试台），全部完成后汇总音频轨道并自动进入视频总成；
  - 点击单模块停止或顶部总停止：立即标记对应取消令牌，更新 `runtime` 状态并保留已完成文件。
- **本地 Windows Python 修复交付**：将完整排查出的 Windows 本地端根因（含 `claude.cmd` 环境变量与管道阻塞修复、Playwright 录屏帧回调、FFmpeg Windows 盘符字幕转义与 `yuv420p` 强制输出、以及生图/配音/配乐前缀对齐与 GPU 锁调度）整理为结构化中文修复手册，内置于应用「说明」列表，支持你直接对照或复制覆盖本地仓库后推送 GitHub。
